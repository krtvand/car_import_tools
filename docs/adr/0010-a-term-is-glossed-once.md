# A term is glossed once, into a committed file

The equipment list and the 注意事項欄 warnings box print English beside every
item on the report. That English comes out of `banzai24/inputs/glossary.json`,
keyed by the term — never from a translation of the card, the box, or the sheet.

A term is sent to Claude the first time this repo ever sees it, by `extract` as
it reads the sheet that printed it or by the `glossary` command backfilling the
database. Everything afterwards is a dictionary lookup. `report` makes no model
call at all.

## Why

**Because a gloss belongs to the term, not to the lot.** The 202 extractions in
`auction.db` print about 620 distinct terms between them and several thousand
uses of them: `PS` and `PW` are on nearly every sheet, `純正ナビ` on most, `後送`
on every car whose spare key is following by post. Translating the *sheet* would
pay for `PS` two hundred times and get a slightly different answer each time.
Translating the *term* pays once, and every card that prints it says the same
thing — which is the half of this that a per-sheet translation could not offer at
any price. An operator learns that `カワ` means leather seats by reading it in
the same words on every card.

The whole backfill of 623 terms cost about $1.30, one time. A morning's run adds
a handful of new terms or none at all, and a sheet that prints nothing new makes
no request.

**Because the report has to stay free to re-run.** `banzai24/report.py` opens by
promising a page that is regenerated by a template tweak rather than a re-fetch —
no network, no browser, no model call. Translating at render time would have
broken that quietly: the first re-render after a CSS change would have been a
bill. Reading a file keeps `report` deterministic, offline, and re-runnable, in
the same way `cars/inputs/trims.toml` keeps the トリム gloss out of it.

**Because a translation you can edit is worth more than one you cannot.** The
file is committed and hand-editable. An operator who disagrees with
"factory-fitted navigation" types over it and it is that way for ever, on every
past and future report. A per-sheet translation would have to be argued with once
per sheet.

## How the file behaves

**The key is folded, the display is verbatim.** Auction houses type in whichever
width their software emits, so `ｴｱB` and `エアB`, `ＳＤ` and `SD` are the same
word arriving twice; keys are NFKC-folded and stripped of decoration (`★`, `！`,
bullets) so the two share one entry and one purchase. Case is *not* folded — `PS`
is power steering and `ps` is nothing. The card still prints exactly what the
sheet printed, decorations and all.

**`null` is an answer.** A term the model read and could not make sense of —
`アルネ`, `ヂー`, the OCR debris of a smudged line — is recorded as `null` and
never asked about again. A term the model *left out of its reply* is not
recorded, and is asked about next time: an answered `null` and a dropped line
look identical in a list of results and are worlds apart, and writing off `欠品`
as unreadable because one batch came back a line short would blank that gloss on
every card for ever.

**Glosses are matched to terms by name, not by position.** The model answers a
batch of sixty terms as a list. Matching by index would file "spare key" against
欠品 the first time an entry was dropped or reordered — silently, and
permanently, since the file is written once and read for ever.

## Consequences

**A new term is missing from the first report that prints it, if `extract`
failed to gloss it.** The glossary update rides on the extraction and is not
allowed to break it: the sheet read is the expensive half and is already in the
database by then, so a translation failure prints a line and the terms wait for
the `glossary` command. The card shows the Japanese alone until then, which is
what it did before this existed.

**The warnings box is split on whitespace, and only on whitespace.** `取保　スペ
アキー　後送` is three facts and renders as three lines. `、` and `・` are *not*
separators here, because they appear inside items as often as between them —
splitting `R5年2月14日走行18380km時、メーター交換` at its comma would file half a
sentence in the glossary for ever. The cost is that a Latin phrase with a space
in it splits (`＊Apple CarPlay対応` becomes two items), which reads acceptably;
the alternative mangles meaning, which does not.

**Sentences end up in the glossary.** A warnings box that is prose contributes
its clauses as "terms", each glossed once and never reused. They are a minority
of the file and cost a few cents; the alternative — a rule that tells a term from
a sentence — would be a guess made on every sheet rather than a line in a file
anyone can delete.

**`warnings_en` is now nearly dead.** The sheet-read prompt still returns a
whole-box English sentence, and the card shows it only when the glossary cannot
read a single term of that box. It is worth keeping while the file is young; when
it stops appearing on any card, the field and its share of the extraction prompt
can go.
